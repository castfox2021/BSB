# Task 11 — 한국식 차트, 리플레이, 실제 체결 복기

## 화면 사용

- **실시간 시장·알림**의 전체 KRW 순위에서 `차트·근거 보기`를 선택한다. 1/3/5분 OHLCV, 현재 호가·스프레드·지연, 예상 슬리피지와 후보 로컬 모델 점수를 표시한다.
- 상승 캔들/거래량은 **빨강**, 하락은 **파랑**, 보합은 회색이다. 매수 실제 체결은 빨간 ▲, 매도는 파란 ▼, 부분체결은 빈 마커, 신호는 노란 원, 주문 요청은 보라색 사각형이다. 툴팁은 정확한 가격 문자열과 UTC 체결 시각의 KST 표시를 제공한다.
- `매수 조건·수량·수수료 확인`, 보유분의 `부분 매도 수량 입력`/`전량 매도 조건 확인`은 기존 DirectTrading 확인 화면으로 이동한다. 기존 활성화·위험검사·미리보기·재확인·전송 경로를 재사용한다. 화면 조회와 차트 선택은 주문하지 않는다.
- **차트 리플레이·복기**에서 한국시간 날짜, 종목, 진입 전략 버전, 승인 모드, 전략/외부 원장을 필터링한다. 원장 요약과 요청 상태는 페이지 이동을 제공한다. 주문 요청·동기화 완료 상태는 실제 체결 성과와 분리한다. 거래소 `cancel` 상태와 앱 `DONE`(조회 동기화 완료)을 구분한다.
- 거래 선택 후 기본 신호/매수 전 30분~청산 후 30분을 재생·정지하거나 슬라이더로 이동한다. 앞뒤 범위는 0~720분, 1/3/5분봉을 지원한다. 차트는 최근 최대 180봉을 표시한다. 날짜는 항상 Asia/Seoul이다.
- 자유 메모/태그는 SQLite에 저장되며 수정 전후를 감사 기록으로 남긴다. CSV는 현재 날짜·종목·전략·모드·원장 필터의 전체 체결을 UTF-8 BOM으로 내보내며 자유 텍스트의 수식 주입을 막는다.

## 저장 구조와 당시 근거

스키마 **7**: `decision_events`, `replay_candles`, `trading_journals`, `trade_reviews` 및 조회 인덱스. DB 백업 후 마이그레이션한다. 스키마 변경과 초기 이관은 같은 트랜잭션이며, 미래 버전 DB는 시작을 거부한다.

- SIGNAL: 실제 신호 payload, 완료 봉 basis, 조건식 전략 버전/파라미터, 정책 임계값, 당시 모델 버전/점수, 공개 Trade/Ticker/Orderbook 스냅샷, feature snapshot, 시장 데이터 나이, 위험관리 판정, 명시적 청산 사유.
- ORDER_PREVIEW / ORDER_REQUEST / ORDER_ACK / ORDER_STATE: 수동/자동 승인 모두 같은 주문 모듈에서 기록. 요청은 체결로 취급하지 않는다. 실제 주문 상태는 조회로 확인하고 중복 요청 방지 경로를 유지한다.
- FILL: 개별 거래소 체결 ID로 중복 방지. 실제 체결 시각·가격·수량과 당시 알려진 수수료를 불변 기록으로 보존한다. 나중에 확인된 수수료는 FILL_FEE 이벤트로 별도 기록한다.
- BOOK: 후보/보유 상세 분석 중 종목별 분당 호가 스냅샷. 실제 신호에서는 별도의 신호 시점 스냅샷을 보존한다.
- decision/replay 테이블의 UPDATE/DELETE는 SQLite 트리거가 거부한다. 메모와 사후 복기는 별도 테이블이며 당시 근거를 덮어쓰지 않는다. 토큰·Authorization·클라이언트 객체를 저장하지 않는다.

## 리플레이의 시간 경계

기준은 **거래소 시각과 수신/보존 시각 모두 커서 이하**이다. 미래 데이터는 응답에서 제거한다. 완성된 REST 봉은 종료 시각도 커서 이하이어야 한다. 현재 mutable `market_candles`를 과거에 그대로 투영하지 않는다.

1분봉 수신 버전을 REST 수신, WS 완료, 후보/보유 상세 분석, 신호 발생, 누락 감지 시 추가 보존한다. 동일 값은 중복 보존하지 않는다. 3/5분봉은 커서까지 알려진 1분봉만 재집계한다. 미수신·보존되지 않은 분은 빈 구간/불완전 상태로 표시하며 가상의 평탄한 봉을 채우지 않는다. 유지 중인 raw WS 이벤트로 보완한 봉은 완전성을 보장하지 않아 부분 데이터로 표시한다. 손절/익절 참고선 역시 커서까지 알려진 체결과 보존된 정책으로만 계산한다.

이전 스키마의 캔들/체결은 **LEGACY_IMPORTED_NOW**로 이관하며 지식 시각을 과거로 소급하지 않는다. 따라서 이미 지나간 거래의 원래 호가/지표가 없으면 정확한 당시 재현이 불가능하다. 실시간 공개 차트에는 이미 수신한 REST 히스토리를 표시할 수 있지만, 그 히스토리를 수신하기 전 과거 커서에서는 공개하지 않는다.

## 손익과 전략 귀속

기존 전략 원장과 동일한 **이동평균 원가**를 Decimal 정밀도 80으로 배분한다. 매수 수수료를 원가에 포함하고 부분 매도마다 원가를 비례 배분하며 매도 수수료를 차감한다. 매수 lot→매도 fill의 수량/원가 배분을 응답에서 확인할 수 있다. 실제 슬리피지는 요청 시 참고가 대비 체결가 차이로 별도 표시하며, 실제 체결 손익에 다시 차감하지 않는다.

청산 이유(STOP_LOSS, TAKE_PROFIT, TIME_EXIT, SIGNAL_EXIT, MANUAL_EXIT, RISK_EXIT 등)와 결과(PROFIT/LOSS/BREAKEVEN)는 독립이다. 위험 청산 엔진 `manual-risk`의 매도 성과도 진입 전략에 귀속하고, 당시 청산 신호 버전은 별도 `decision_strategy_version`으로 보존한다. 서로 다른 진입 전략의 매수를 수동 혼합한 포지션 청산은 `MIXED_ENTRY_VERSIONS`로 명시한다.

앱에서 가져온 실제 체결과 사용자 확인 등록 체결만 전략 원장에 포함한다. 다른 Private 체결은 EXTERNAL 원장으로 분리하고 이중 집계하지 않는다. 이전 매수 원가 또는 수수료가 없으면 순손익을 `null`로 표시하며 0원 원가나 수익을 만들어 내지 않는다. 일별 실현손익은 그 날의 매도 체결 기준, 승률은 그 날 완전 청산한 포지션 기준이다. 실전 자본 150,000원/신규 매수 50,000원/일일 손실 진입 차단 3,000원 정책을 유지한다.

## 사후 로컬 분석

요청한 거래만 별도 worker thread에서 배치 복기한다. 장점/문제/개선 가설, 동일 진입 버전의 유사 청산 거래, 일별 전략 순손익을 제공한다. 당시 보존된 AI 점수는 원래 점수로 표시하고, 당시 basis 10개 완료 봉과 현재 로컬 로지스틱 모델이 있으면 **현재 모델 사후 재추론**을 별도로 수행한다. 현재 모델의 학습 데이터에 해당 거래가 포함됐을 수 있으므로 이를 검증 성과로 표시하지 않는다.

모델 또는 원래 basis가 없으면 `규칙 기반 복기 · AI 미사용`이라고 표시한다. 외부 LLM/API 호출과 API 비용은 없다. 자연어 규칙 결과를 LLM 분석으로 가장하지 않는다. 사후 분석은 실전 전략·주문 승인에 반영하지 않는다.

## 검증 및 운영 한계

- Python 전체 회귀 테스트: 부분/분할 체결, 수수료, 이동평균 원장 일치, 수동/자동 같은 기록, 청산 이유와 손익 분리, UTC/KST 날짜 경계, 중복 이벤트, 메모 재시작 지속, CSV, 누락 원가, 불변 이벤트, 미래 봉/복구/신호/체결/수수료/참고선 차단.
- 웹 테스트: canonical localhost와 실제 127.0.0.1 Host가 달라도 동일 출처 메모 저장, 외부 Origin 차단, CSV 응답 형식 유지, 미허용 주문·출금·취소 경로 차단.
- 별도 `/tmp` 원장/무키 API/별도 웹 포트에서 가상 KRW-TESTONLY 체결로 색상·마커·재생·정지·3분봉 전환·시간 이동·메모·복기를 확인했다. `task-11-chart-ui.jpg`는 이 **가상 거래** 화면이다. 운영 원장에 가상 거래를 넣지 않았다.
- 실거래 전송 테스트는 수행하지 않았고, 자동매매를 활성화하거나 실전 전략을 승격하지 않았다. 재시작하면 기존 정책대로 정지한다.
- 원본 기록이 없는 과거 구간은 재현할 수 없다. raw 이벤트는 기존 최근 50,000개 보존 정책을 유지하며 추가 불변 봉/판단 기록은 디스크를 사용한다. 장기 운용에는 원장 백업과 디스크 용량 관리가 필요하다.
