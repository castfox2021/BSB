# Task 12·13 — 조용한 가상매매 신호판

## 현재 운영 기준

Task 13을 현재 운영 기준으로 적용한다. 프로그램은 기존 PAPER 엔진으로 가상매매하고, 사용자는 빗썸에서 직접 실제 매매한다. 현재 서비스는 `QUIET_FOLLOW / PAPER / USER_EXTERNAL_MANUAL`이며 **API 실전 주문을 전송하지 않는다**. Task 12의 체결 중심 화면·큰 글씨·매수 초록/매도 빨강·최신순·차트 연결은 유지하고, 자동 알림 요구는 Task 13의 조용한 운영 지시로 대체했다.

기존 실전 주문 모듈과 테스트는 미래 별도 운영을 위해 유지한다. 현재 앱 시작 시 `ManualOrders.live_execution_disabled=True`를 설정하며 `ready()`에서 활성화·미리보기·전송·전송 직전 재검사를 차단한다. 자동 승인도 같은 경로를 사용한다. 브라우저에서 버튼을 숨기는 것에 의존하지 않는다. 기존 접수 주문의 **읽기 전용 복구/체결 기록**은 차단하지 않는다. 실전 기능을 다시 허용하는 UI/API 모드 전환은 이번 작업에 제공하지 않는다.

## 메인 화면

상단은 가상매매 / 실전 직접 매매·API 주문 꺼짐, 오늘 가상 실현손익, 가상 보유 수, 선택 전략 버전을 표시한다. 본문은 세 영역이다.

1. **가장 최근 가상매수**: 마켓 코드, KST 체결 시각, 가상 체결가, 신선한 현재가, 매수 이후 가격 변화, 신호 경과, 비용 포함 가상 금액, 한 줄 사유와 상태.
2. **현재 가상보유**: 종목, 가상 평균 체결 매수가, 현재가, 예상 청산 비용을 포함한 평가손익과 수익률. 실전 계좌와 별개다.
3. **최근 가상매도**: KST 시각, 가상 체결가, 수수료 반영 실현손익의 명시적 +/- 부호, 익절·손절·시간 청산 사유.

매수·양수 손익은 초록, 매도·음수 손익은 빨강이다. **캔들 자체의 상승 빨강·하락 파랑은 한국 기준을 유지**한다. 체결 화살표는 매수 초록·매도 빨강으로 구분한다. 메인에는 소리·팝업·토스트·브라우저 알림 코드가 없으며, 자동 알림 컴포넌트를 마운트하지 않는다. API도 현재 모드의 effective notification 상태를 모두 false로 반환한다. 이전 알림 저장값이 있어도 이 신호판은 알림을 호출하지 않는다.

거래 ID는 `paper_trades`의 고유 ID이며 폴링 결과를 배열에 추가하지 않고 기존 영역의 데이터만 교체한다. 새로고침·재시작 후에도 SQLite에서 같은 기록을 조회한다. 매수/매도는 각각 페이지 이동하며, 오늘 손익·보유 상태는 표시 페이지와 무관하게 계산한다. 선택한 전략 한 버전의 독립 가상 자본 150,000원만 메인에 표시하며 여러 실험 계좌를 합산하지 않는다.

## 표시 기준과 데이터 정합성

`시스템 설정`에서 추종할 가상 전략 버전, 최근 기준(기본 120초), 오래된 기준(600초), 추격 주의 상승률(0.01=1%)을 저장한다. 전략 버전은 저장되어 새 실험 버전이 생겨도 자동 교체되지 않는다. 이 설정은 **표시 기준**으로, 전략 조건·실전 승인 버전·주문 한도를 바꾸지 않는다.

- `최근`: 최근 시간 범위이며 가격 상승이 추격 주의 기준 미만.
- `추격매수 주의`: 최근 시간 범위 초과 또는 기준 이상의 가격 상승.
- `오래된 신호`: 오래된 기준 시간 이상.

상태는 매수 권유가 아니다. 가격·수익률은 실시간 수신 여부, 연결 상태, 15초 수신 나이/거래소 지연 검사를 통과한 값만 사용한다. 신선도가 없으면 `시세 지연`을 표시하고 현재가·변화율·평가손익은 null로 반환한다. 오래된 마지막 가격을 새 현재가로 표시하지 않는다.

가상 체결은 실제 PAPER 기록만 표시한다. 신호나 주문 요청을 체결로 변환하지 않으며 `simulated=true`, `channel=PAPER`를 확인한다. 기존 sweep의 호가 잔량·수수료 0.04%·슬리피지 0.1% 계산과 진입/청산/위험관리 조건은 그대로다. PAPER payload에 **표시용 체결가, 신호 시각, 한 줄 사유, 전략/basis 스냅샷**만 추가했다. 신규 손절·익절·매수 조건 또는 주문 금액 변경은 없다.

과거 가상 기록은 저장된 금액·수량·수수료가 모두 있으면 체결가를 산술 복원하고 `derived_fill_price`로 구분한다. 기록이 부족하면 임의 추정하지 않는다. 원래 신호 시각이 없으면 `가상 체결 후 경과`로 표시한다. 당시 세부 이유가 없는 거래도 사후 이유를 만들어 원래 사유로 표시하지 않는다.

## 상세 메뉴와 실제 체결 비교

- **매매 차트**: 가상 체결 클릭 시 해당 종목 차트와 보존된 사유를 표시한다. 가상 마커는 `가상 체결`로 표시하며 실제 거래소 체결로 표현하지 않는다. 체결 당시까지 수신한 캔들만 보는 선택도 유지한다. 전체 KRW 스캐너·지표·호가 상세는 이 메뉴의 접힌 영역에서 연다.
- **매매노트**: 가상 이력, 실전 일지/리플레이, 실제 확인 체결 수동 등록, Private 계좌 조회를 분리한다. 실전 화면의 매수·매도 요청 버튼은 비활성화한다.
- **전략 분석**: 버전별 가상 순손익·실현 수익률·비용·매도 체결 수와 해당 전략으로 귀속된 실제 확인 체결 순손익을 비교한다. 1,000개 제한 요약을 재사용하지 않고 전체 저장 기록을 집계한다. 각 가상 계좌의 자본은 독립이다. 비용·실행 지연·미귀속 체결 때문에 동일 조건의 인과 비교가 아니라는 점을 표시한다.
- **시스템 설정**: 표시 기준과 운용 정책·수집 상태를 제공한다. 미래 API 실전 기능은 비활성 표시만 유지한다.

가상 체결 상세의 `빗썸에서 직접 실행한 실제 체결 등록`은 실제 주문을 전송하지 않는다. 종목·매수/매도 방향만 선택하고 사용자가 실제 수량·가격·수수료를 입력해 확인한다. 실제 체결은 가상 신호 이후 시각이며 종목·방향이 맞아야 연결된다. 기존 `manual_fills` 저장과 같은 트랜잭션에서 `PAPER_FOLLOW_LINK` 불변 이벤트로 가상 거래 ID/전략 버전을 보존한다. 재시도는 같은 체결 ID를 사용하고, 중복 저장 또는 기존 귀속 변경을 거부한다. 가상 수량·가격을 실제 체결 입력값에 자동 복사하지 않는다.

이 연결은 실전 전략 승격이 아니다. 실제 이동평균 원가·수수료·순손익은 기존 원장 계산을 사용하며, 가상 금액을 실전 자본으로 옮기지 않는다. 전략별 비교는 명시적으로 연결된 실제 체결만 귀속한다. 계좌에서 가져온 미귀속 외부 체결은 기존 정책대로 별도다.

## 저장/API/변경 파일

스키마 버전은 기존 **7**을 유지한다. 표시 설정은 기존 `strategy_state`의 `quiet_board` 키, 실제 수동 추종 연결은 기존 `decision_events`, 가상 이력은 기존 PAPER 테이블에 저장한다. `paper_board_history` 조회 인덱스를 추가하며 기존 데이터는 삭제하지 않는다.

- `GET /api/board?buy_page=1&sell_page=1&page_size=5`
- `PATCH /api/board/preferences`
- `GET /api/board/trades/{id}`: 원래 저장된 가상 상세 근거. 메인 API는 큰 basis/전략 스냅샷을 제외한다.
- `GET /api/board/comparison`
- 기존 `POST /api/manual-fills`: 선택적 `paper_trade_id` 추가. 여전히 사용자 실제 체결 확인이 필수다.

신규: `quiet_board.py`, `quiet-board.tsx`, `quiet-types.ts`, `quiet-details.tsx`, `quiet-settings.tsx`, `strategy-comparison.tsx`, `manual-fill-panel.tsx`, `test_quiet_board.py`, `quiet-display.spec.ts`.

수정: `app.py`, `manual_orders.py`(현재 운영 모드 차단), `engine.py`(가상 체결 기록 metadata만), `trade_review.py`(실제 체결의 가상 전략 귀속), `page.tsx`, `trading-review.tsx`, 로컬 API proxy, README.

## 빈 화면의 작동 상태 구분 보완

새 버전 `00100174…`의 체결 0건 화면만으로는 정상 대기와 장애를 구분할 수 없어, 실제 엔진 루프 성공 시각과 버전별 가상 진입 검사 진단을 추가했다. 계좌 `last_bar`는 거래 상태가 바뀔 때만 갱신되므로 엔진 heartbeat로 사용하지 않는다.

신호판에는 마지막 분석 시각·시세 연결 수·정상 감시/시작/시세 대기/분석 지연/엔진 오류 상태를 표시한다. 체결 0건 영역에서 대기 이유와 현재 조건을 펼쳐 볼 수 있다. 화면을 채우기 위한 가상 거래 생성 또는 전략 조건 완화는 하지 않았다. 첫 로컬 API 확인은 도구의 네트워크 접근 제한 영향을 받았으며, 권한 있는 재확인에서는 기존 서버가 실행 중이었다. 이를 실제 서버 중단으로 판단하지 않는다.

로컬 실행을 터미널과 분리하는 `npm run manual:start`, 소유 프로세스와 두 로컬 포트를 확인하는 `npm run manual:status`, 이 checkout의 정확한 runner PID만 종료하는 `npm run manual:stop`을 추가했다. 로그인 자동 시작/실전 활성화 기능은 아니다. PID·로그는 Git 제외 `data/runtime`에 0600 권한으로 저장한다. start는 기존 프로세스 또는 사용 중인 포트가 있으면 중복 기동하지 않는다.

최종 Python 171개, 웹 17개 테스트와 빌드 통과. 운영 UI에서 489종목 연결·최근 분석 시각 갱신·안전검사 통과 후보 0·새 전략 체결 0을 확인했다. 실제 주문 비활성화와 기존 매수·매도 조건은 유지한다. 화면 검증 이미지는 `quiet-board-runtime-status.jpg`다.
