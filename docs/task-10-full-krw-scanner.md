# Task 10 — Full KRW Market Scanner

2026-11-11. 전체 종목 수를 코드에 고정하지 않는다. 상위 20종목·24시간 거래대금 30억 원 기준은 제거했다. 저가/소형 코인도 동일한 감시 대상이며, 실제 매수는 유동성·데이터·전략·계좌 위험 조건을 별도로 검사한다. 자동매매를 활성화하거나 실주문을 보내는 개발 검증은 하지 않는다.

## 수집과 전체 분석

GET `/v1/market/all?isDetails=true`를 시작 시 및 300초마다 조회한다. 신규 KRW는 즉시 다음 구독에 추가하고, 목록에서 제거된 종목은 신규 주문을 차단한다. Ticker의 거래 지원·유의·정지 정보도 검사한다. 전체 Trade/Ticker는 운영상 연결당 100종목 배치로 분할한다. 실제 종목 수는 목록에서 계산하며, 100은 전체 감시 제한이 아니라 보수적인 구독 배치 크기다. 연결 요청을 전역 초당1회로 분산하고 재연결은 백오프하며 429/418은 대기한다.

시세 수신은 정규화·최신성 확인·메모리 통계 갱신 후 bounded queue로 넘긴다. SQLite는 작업 스레드에서 최대 200체결씩 원자적 배치 저장한다. 전체 종목 1분봉을 생성하고 전역 분봉 시계가 완료 1분봉으로 3·5분봉을 합성한다. 중복 ID는 통계/저장 양쪽에서 제거하며, 닫힌 봉의 뒤늦은 체결은 절대 REST 값으로 복구한다. 빈 분을 임의 OHLC로 만들지 않는다.

진행 중 최근 5개 분 구간과 직전 5개 분 구간의 거래량·거래대금·가격 변화를 계산한다. 초기 기준 미확보와 실제 0 거래량을 구분한다. 0 기준은 무한대 비율 대신 ‘거래 발생’을 표시한다. 거래량/대금 증가, 가격 변화, 알려진 매수/매도 체결 비중으로 모멘텀을 계산하고 거래대금 규모로 후보를 배제하지 않는다. 처음에는 기준 데이터 준비가 필요하며 초기 REST 로딩은 공통 초당5회 제한기를 따른다.

EARLY_SURGE는 활발도 증가·상승 움직임의 관찰 신호다. 미검증이며 자동 주문 대상 BUY_CANDIDATE로 바꾸지 않는다. 기존 승인 전략이 실제 진입 조건을 충족한 BUY_CANDIDATE만 자동 실행한다. 기존 운용 자본 150,000원·주문 50,000원 상한·일일 손실 기준 3,000원·중복 방지·원장 기록은 유지한다.

## 후보 상세 분석과 부하 조절

기본 통계는 전체 종목을 매초 계산한다. 호가 구독·깊이/슬리피지 분석·모델 추론은 후보에 한정하고, 사용자가 직접 선택한 종목과 보유 종목은 호가 분석 예외로 추가한다. 실전·모의 보유분은 별도 연결로 고정하며, 후보 연결을 교체할 때 보유 연결이 준비되기 전 기존 연결을 끊지 않는다.

기본 상세 용량 64는 동시에 처리하는 작업 예산이다. 절반은 높은 모멘텀, 나머지는 후보 전체 순환으로 선정해 계속 같은 종목만 처리하지 않는다. 이 용량은 전체 감시/후보 탐지의 종목 수 제한이 아니다. 과부하 시 상세 용량을 줄이고 상세 간격을 2초에서 10초로 늘리되, 보유분의 구독과 위험 시세 확인은 유지한다. 모의 신규 진입 분석도 감속하며 기존 모의 보유분은 계속 확인한다. 전략 계산과 DB I/O는 수신 이벤트 루프에서 분리한다.

체결 queue가 넘치거나 저장이 지연되면 해당 종목의 현재 분을 누락 상태로 기록하고 매수를 차단한다. 다음 체결이 누락 플래그를 지우지 않는다. 누락된 분이 닫힌 뒤 REST로 확인될 때까지 복구를 재시도한다. 체결 ID는 비연속일 수 있으므로 단순 번호 점프를 누락으로 단정하지 않는다. 데이터 누락을 완벽히 증명하는 체결 연속번호 계약은 가정하지 않는다.

## 실전 매수 검사

- Trade/Ticker/Orderbook 연결·REALTIME·15초 최신성·교환 시각 편차
- 거래 지원·정지·유의 정보, 이상 가격 급변 안정화, 저장 누락/지연
- 정상 스프레드, 양방향 잔량, 실제 계획 예산에 대한 매수 VWAP 예상 슬리피지
- 완료·연속 캔들, 승인 전략/검증 유효기간, 실제 계좌 및 고정 자본 위험관리

전체 감시와 유동성 통과, 최종 주문 승인은 서로 다르다. 자동매매의 고정 매수 예산을 후보 유동성 검사에 반영한다. 실제 주문 직전에는 입력 금액과 현재 호가로 다시 검사한다. 평상시 슬리피지는 정책의 execution_slippage_rate를 따르며 시장가 최종 체결가격을 보장하지 않는다. 데이터가 불확실하면 새 매수는 차단하고, 신선한 유효 호가가 있는 보유분 위험 감시와 청산 신호는 유지한다.

## 로컬 모델

`scanner_model.py`는 표준 Python으로 동작하는 로지스틱 모델이다. 실제 로컬 완료 봉에서 5분 거래량/대금 배수와 가격 수익률 특징을 만들고, 다음 완료 3분 수익률이 비용 가정을 초과했는지를 학습한다. 입력 특징은 미래를 사용하지 않는다. 시간순 학습 70%/검증 30%를 분리하고 경계를 넘는 학습 레이블을 제거한다. 정규화는 학습 데이터만 이용한다. 학습은 작업 스레드·최대 5,000표본·60회 반복으로 제한한다.

모델 파라미터·검증 정확도·단순 다수 클래스 기준·Brier 점수·학습/검증 시각을 해시 버전으로 보존한다. 추론은 후보의 완료 봉에만 실행한다. 표본/클래스가 부족하면 UNTRAINED이고 확률을 만들지 않는다. 모델은 EXPERIMENTAL_ADVISORY이며 실전 전략이나 주문 승인에 영향을 주지 않는다. 초기 후보 특징·상세 결과는 최대 50,000개 관찰 기록으로 보존해 후속 연구에 사용할 수 있다. 외부 AI API로 자료를 전송하지 않는다.

## 화면과 API

GET `/api/market/scanner?page=1&page_size=20&candidates_only=false`

전체 순위는 20/50/100종목씩, 종목·소수점 가격·5분 거래량/거래대금 증가·가격 변화·모멘텀·체결 비중·상세/매수 상태·예상 슬리피지·AI 참고 추론을 표시한다. 실시간 순위는 변동하며, 이력 페이지의 고정 스냅샷과는 다르다. 전체 분석 수, 최신성 확보 수, 초기 후보 수, 상세 호가 대상 수, 데이터/유동성 통과 수, 실전 보유 감시 수를 별도 집계한다.

SQLite schema 6: scanner_models, scanner_observations와 대기 캔들/학습 조회 인덱스 추가. 이전 DB를 백업한 후 마이그레이션한다. 실제 키나 private 원문은 모델 데이터나 검증 기록에 포함하지 않는다.
